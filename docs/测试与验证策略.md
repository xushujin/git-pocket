# 测试与验证策略

## 原则

二进制格式（packfile / index / object）不能只靠"编译通过"验收，必须用**真实 git 产物对拍**。
`core:git` 是纯 JVM 模块，所有验证都在 JVM 单测里完成，不需要模拟器。

## 已实现的验证（`./gradlew :core:git:test`）

| 测试类 | 覆盖点 | 对拍方式 |
|---|---|---|
| `ObjectDatabaseTest` | loose object 读写、SHA-1、commit/tree 编解码、gpgsig 多行、损坏对象拒绝 | 自校验 + 已知 oid |
| `PackFileTest` | pack idx v2、ofs/ref delta、pack 校验和、commit 解析 | `git gc --aggressive` 生成真实 pack；`git cat-file -p` 逐对象比对 |
| `GitIndexTest` | index v2 读取、写回、stage 新文件、stageAll（含删除） | `git ls-files --stage` / `git status --porcelain` / `git cat-file -p :path` |
| `GitRepoTest` | init、stage、commit、log、status、diff、空提交拒绝 | `git rev-parse HEAD` / `git log` / `git ls-tree` / `git fsck --strict` |
| `LineDiffTest` | 相同/替换/新增/删除/多 hunk/超大降级/二进制/空文件 | 断言 hunk 结构 |

## 真实文件验证的具体做法

1. 用 `ProcessBuilder` 调真实 `git`（`GitCli` 工具类），在临时目录建仓库。
2. 制造相似内容后 `git gc --aggressive --prune=now`，强制产生 pack 与 delta。
3. 用本引擎读取，与 `git cat-file -p` 输出逐字节比较。
4. 反向验证：本引擎写出的 index/commit，交给真实 `git status` / `git fsck --strict` 检查。
5. 环境没有 git 时用 `Assume.assumeTrue` 跳过；CI 上必须全部执行（不允许跳过）。

## 手工 fixture

```bash
./scripts/gen-fixtures.sh /tmp/gitpocket-fixtures
git -C /tmp/gitpocket-fixtures/repo fsck --strict
```

生成的仓库包含：多分支、合并提交、二进制文件、大文件，可用于真机手工验证。
