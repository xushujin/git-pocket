# 数据迁移手册

## 硬规则

1. `exportSchema = true`，schema JSON 必须提交（`core/database/schemas/<dbClass>/<version>.json`）。
2. **禁止** `fallbackToDestructiveMigration()` / `fallbackToDestructiveMigrationOnDowngrade()`。
   迁移缺失时宁可抛错进入只读安全模式，也不能删用户数据。
3. 只增不删：删除列/表至少跨两个版本（vN 停读写，vN+2 物理删除）。
4. 新增 `NOT NULL` 列必须带 `DEFAULT`，或分两步（先可空 → 回填 → 重建表）。
5. 迁移里只做结构与数据回填，不调用 Repository、不发网络。
6. 每个迁移必须配 `MigrationTestHelper` 用例，且覆盖 n-2 → n 的直达路径。

## 当前版本

- 数据库版本：**2**
- `MIGRATION_1_2`：`repo` 表新增 `defaultBranch TEXT`（可空），并回填 `'main'`。
  选择可空而非 `NOT NULL DEFAULT`，是为了后续允许"未知默认分支"的语义。

## 新增一个迁移的步骤

```kotlin
// 1. 修改 Entity，并把 @Database version 从 N 改成 N+1
// 2. 新建 core/database/src/main/kotlin/.../migration/MigrationNToN1.kt
val MIGRATION_N_N1 = object : Migration(N, N + 1) {
    override fun migrate(db: SupportSQLiteDatabase) {
        db.execSQL("ALTER TABLE repo ADD COLUMN newColumn TEXT")
    }
}

// 3. 注册到 Migrations.ALL
val ALL: Array<Migration> = arrayOf(MIGRATION_1_2, MIGRATION_N_N1)
```

```kotlin
// 4. androidTest：MigrationTest
@Test
fun migrate1To2() {
    helper.createDatabase(TEST_DB, 1).apply {
        execSQL("INSERT INTO repo(...) VALUES (...)")
        close()
    }
    val db = helper.runMigrationsAndValidate(TEST_DB, 2, true, Migrations.MIGRATION_1_2)
    // 断言列存在且数据被回填
}
```

## 如何验证迁移正确性

| 手段 | 说明 | 状态 |
|---|---|---|
| 编译期 schema 校验 | Room 在 KSP 阶段比对 Entity 与 schema JSON，改了表没升 version 会直接编译失败 | ✅ 已生效 |
| `MigrationTestHelper` | 建 vN 库 → 插数据 → 迁移 → 校验 schema 与数据 | ⚠️ 已编写，需模拟器执行 |
| 真机覆盖安装 | 装 vN release → 造数据 → 覆盖装 vN+1 → 检查数据 | ⏳ 发版前执行 |
| 大数据量 | 1 万条草稿 + 5 万条 commit_cache 迁移耗时 | ⏳ 待补 |

## 回滚预案

| 场景 | 行为 |
|---|---|
| 迁移缺失 | Room 抛 `IllegalStateException`，由上层捕获后进入"只读安全模式"并提示升级 |
| 迁移失败（磁盘满 / 约束冲突） | 迁移事务回滚；升级前自动备份到 `cacheDir/db-backup/v{old}-{ts}.db`（保留 3 份 / 7 天） |
| 用户降级安装（DB 版本 > 代码版本） | 不提供降级迁移，提示"请升级应用"，进入只读模式 |

> 备份与安全模式尚未接入代码，当前版本仅保证"不删库"（无 destructive fallback）。
